# BAG.ru.com

*[English version](README.md)*

Одностраничный магазин рюкзаков, собранный в феврале 2018-го на React 16 и Redux: каталог с
описаниями, ценами и счётчиком корзины в шапке. Я сделал его, чтобы продавать рюкзаки, — чем тогда
и занимался.

---

## Проблема

Я продавал рюкзаки, и людей надо было куда-то отправлять. Каталог — маленькая задача с двумя
неудобными местами.

- **Корзина живёт в шапке, а кнопки — в карточках.** Нажатие «положить в корзину» внутри карточки
  товара должно обновить счётчик тремя уровнями выше, в другой ветке дерева. Протаскивать колбэк вниз
  и количество наверх через каждый промежуточный компонент — так страница каталога и превращается в
  трубопровод из пропсов.
- **Товары — это контент, а не разметка.** Сегодня пять рюкзаков, через месяц пятнадцать. Если новый
  товар означает правку JSX, то добавление товара навсегда остаётся задачей разработчика.
- **Рюкзак продаёт фотография.** Текст описания весит меньше, чем снимок, а снимок должен быть
  чётким на телефоне и не весить три мегабайта на десктопе, — то есть нужно несколько размеров
  каждого кадра, а не один.
- **Магазин не должен выглядеть учебной работой.** Один человек, дизайнера нет.

## Решение

Redux ровно ради одного — корзины. `ItemsList` диспатчит `addItem`, редьюсер `basket` дописывает
элемент в массив, `HeaderMenu` читает длину через `connect`. Карточка товара и счётчик друг о друге
не знают, и никакой колбэк через середину дерева не тянется.

Товары лежат в [`src/db/items.js`](src/db/items.js) массивом объектов: id, название, цена, фото,
описание. Добавить товар — это добавить объект, в компонентах не меняется ничего. Имя папки не
случайное: это база данных в единственном смысле, который сайту был нужен.

Каждый снимок рюкзака выгружен в 200/400/800 px рядом с оригиналом, чтобы карточка просила тот
размер, который ей действительно нужен.

Вёрстка — Bootstrap 3 через `react-bootstrap`, шапка с параллаксом на слушателе скролла в
`HeaderMenu`.

## Как запустить

Проект — Create React App начала 2018 года, поэтому современной Node нужен флаг legacy OpenSSL:

```bash
git clone https://github.com/ZergMaster/bagrucomReact.git && cd bagrucomReact
npm install
NODE_OPTIONS=--openssl-legacy-provider npm start     # http://localhost:3000
```

Товары — в [`src/db/items.js`](src/db/items.js), их фотографии — в `src/img/bags/`. Это всё, к чему
надо прикасаться, чтобы поменять каталог.

**Одну вещь пришлось починить, чтобы дойти сюда:** `redux` и `react-redux` импортировались по всему
коду, но отсутствовали в `package.json`, поэтому из чистого клона проект нельзя было ни поставить,
ни запустить. Теперь они в зависимостях — скриншот выше это и есть настоящий запуск этого
репозитория в 2026-м.

## Кто пользовался и что это дало

Я и пользовался — продавал рюкзаки. Это настоящий магазин настоящего маленького дела, а не учебное
упражнение: телефон в шапке мой, товары те, что были.

Как рабочий образец это самый старый React в профиле, и это видно: классовые компоненты,
`PureComponent` с присвоением `this.props` руками, Bootstrap 3, папка `db`, которая на самом деле
массив в JS. Я не буду делать вид, что это были хорошие решения, и сегодня ни одного из них не
повторил бы.

На что стоит смотреть — так это на единственное архитектурное решение, которое было верным и таким
осталось: каталог — данные, компоненты — рендерер, а добавление товара не является правкой кода.
Через два года в Playkot ровно это разделение — контент как данные, которые правит неинженер, и код
как то, что их отрисовывает, — стало основой всего LiveOps-пайплайна. Здесь оно же, только с пятью
рюкзаками внутри.
